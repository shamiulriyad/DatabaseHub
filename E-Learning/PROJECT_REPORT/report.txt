1. Introduction
- Brief overview: This project implements an E-Learning platform with competitions (coding/MCQ), community features, courses, and admin tools.
- Objective: Show database design, key SQL queries, and competition question flow (admin vs participant views).

2. Entity-Relationship Diagram (ERD)
- Attach the ERD image file here (export from your ERD tool and place in `PROJECT_REPORT/erd.png`).
- Description of major entities:
  - `User` (id, name, email, role)
  - `Competition` (id, title, description, start_time, end_time, status, creator_id)
  - `CompetitionQuestion` (id, competition_id, text, options, correct_answer, points, order)
  - `CompetitionParticipant` (id, competition_id, user_id, joined_at)
  - Other related entities: `Course`, `Enrollment`, `Review`, `Clan` (see codebase DTOs for full schema)

3. Relational Schema (tables and key columns)
- `Users(user_id PK, name, email, role, ... )`
- `Competitions(competition_id PK, title, description, start_time, end_time, status, creator_id FK->Users)`
- `CompetitionQuestions(question_id PK, competition_id FK->Competitions, question_text, options_json, correct_answer, points, question_order)`
- `CompetitionParticipants(id PK, competition_id FK->Competitions, user_id FK->Users, joined_at)`
- Notes: `options_json` stores multiple-choice options (JSON array). `status` values: Draft, Scheduled, Ongoing, Completed.

4. Sample SQL (see `sql_queries.sql` for full file)
- Table creation snippets and sample inserts are in `sql_queries.sql`.
- Example: How to fetch participant-visible questions (no correct answers):
  SELECT question_id, competition_id, question_text, options_json, points, question_order
  FROM CompetitionQuestions
  WHERE competition_id = @competitionId
  ORDER BY question_order;

5. Key SQL Queries and Explanations
- Create tables, insert sample data, sample select queries, and joins for leaderboard, participant checks.
- Explain authorization rules implemented in backend: admin/creator endpoints return `correct_answer`; participant endpoint hides correct answers and requires `status = 'Ongoing'` and participant membership.

6. Competition Flow
- Admin/creator: can view questions via `/api/competitions/{id}/admin/questions` (returns correct answers and metadata).
- Participant: can view questions via `/api/competitions/{id}/participant/questions` only during Ongoing and if registered.
- Frontend behavior: `CompetitionDetail.jsx` selects endpoint based on `user.role` and `competition.creatorId`.
